# Local factory boundaries

- **Before** "State the exit condition as a checkable predicate before the first iteration" freeze the Ticket scope and verify the actual owner identity or a scope-valid owner approval. Record separately authorized collection and installation limits. A general unattended-work request does not widen them.
- **In** "Each iteration makes the smallest change the evidence justifies" retain the Ticket's count across runs and scope changes. At most three automatic reworks are allowed after the first candidate. Stop on unknown execution outcomes, exhausted budget or unavailable independent review.
- **Before** "Stop when the predicate is met" verify evidence against the exact candidate and distinguish synthetic probes, historical live acceptance and current live acceptance. Missing evidence is blocked. A probe of `tools/factory_gate.py` is not an authenticated GitHub adapter, an independent agent run or accepted orch recovery.
- **Before** "Open every PR ready, never as a draft" require independent cold review of the candidate and a scan of changed files and new Git history for private data. Publish only safe summaries. Keep personal databases, browser history, local paths and desktop screenshots local.
- **After** "Post the URL and keep building" leave merge and automatic Trigger activation unarmed. The human owns merging. Continue authorized reversible work, but end a Run when it reaches a genuine permission or unresolved execution boundary.

The original global pstack files stay unchanged. The offline gate is a prototype for admission and result association. A production adapter must authenticate API inputs, reconcile fresh scope before transitions, run independent workers and verify reported artifacts. See [probe boundaries](../../docs/factory-probe.md).
